# 快速开始

## 系统要求

- Windows 10 或 Windows 11（64 位）。
- 首次启动需要网络连接，用于准备 Python 运行时、Python 依赖和 FFmpeg。
- 建议使用 SSD 存放大型索引。
- 构建和加载大型索引需要足够的磁盘空间与内存。

程序采用当前用户安装模式，不要求管理员权限。默认索引目录位于软件安装目录下的 `index` 文件夹；设置、收藏、历史与索引注册信息位于当前用户的应用数据目录。

## 安装与首次启动

1. 从 [GitHub Releases](https://github.com/Cyrene2008/AudioSeeker/releases) 下载最新的 Windows 安装包。
2. 运行 `AudioSeeker_<版本>_x64-setup.exe`。
3. 首次启动时，程序会自动完成以下工作：
   - 在软件安装目录准备独立 Python 运行时；
   - 安装后端所需的 Python 依赖；
   - 检查系统 FFmpeg，缺失时下载到软件安装目录；
   - 启动仅监听本机回环地址的后端服务。
4. 等待启动页完成即可进入主界面。如果准备时间较长，可以跳过等待直接进入界面，后端会在后台继续启动。

## 构建索引

1. 打开「构建索引」，选择「新建索引」。
2. 选择包含音频文件的目录。支持 WAV、FLAC、MP3、OGG、OGA、OPUS、AAC、M4A、MP4、WMA、AIFF、AIF 等常见格式，也支持多种格式混合存放。
3. 输入索引名称。
4. 设置线程数：并行进程数，默认 8，上限 64。
5. 设置目标段加载内存（MB）：
   - 表示每个索引段预计加载到内存时的目标大小，`0` 表示不主动分段（单段）；
   - 单个大型文件不会被拆分，实际内存占用可能高于目标值；
   - 数值越大，分段越少，匹配时单次加载更快，但内存占用更高。
6. 根据目录结构决定是否启用递归扫描：
   - 未启用时只扫描所选目录的第一层；
   - 启用后会进入所有子目录，因此不会显示“只扫描第一层”的确认提示。
7. 点击「开始构建」，任务卡片会实时显示进度、日志和完成统计。
8. 构建支持断点续建：同一任务中断后可重新开始，已处理完成的文件会被跳过。

## 增量构建

1. 切换到「增量构建」。
2. 选择已有索引和音频源目录。
3. 程序会使用该索引首次构建时记录的段内存（MB）作为默认值；旧版或外部导入的索引没有元数据时默认显示 `0 MB`，可手动调整。
4. 开始构建后，仅未进入索引的新音频文件会被处理，已存在的文件自动跳过。

## 检索音频

1. 打开「开始检索」，选择索引或索引分段。
2. 选择样本音频（支持与索引构建相同的格式列表）。
3. 按需调整检索参数：
   - 从/到（秒）：只使用样本的指定时间段；
   - 最小命中：单个命中簇最少对齐哈希数；
   - 最低置信度（%）：留空时按样本时长自动调整。
4. 点击「开始检索」。检索进度无法准确量化，界面使用不确定进度环。
5. 检索任务跨页面持续：切换到其他页面不会取消检索，返回检索页后仍会显示运行状态，完成后直接显示结果。

## 结果操作

| 操作 | 说明 |
| --- | --- |
| 播放 | 从匹配到的文件偏移开始播放，一直播到源文件结尾，跨页面持续播放 |
| 收藏 | 点击空心星加入收藏；再次点击实心星取消收藏 |
| 定位 | 在 Windows 资源管理器中定位源文件 |
| 合并同名文件 | 将同名结果合并为一行，使用其中最高的置信度展示 |
| 导出所选 | 按样本时间线拼接选中的匹配结果并保存为 WAV |
| 导出全部 | 导出全部匹配结果的拼接结果 |

## 检索历史

每次检索完成后会自动保存到历史列表。历史记录包含样本、索引、结果数与时间，可随时载入再次查看或导出。

## 设置

- **深色模式**：切换浅色/深色外观。
- **语言**：中文 / English 界面切换。
- **默认索引保存位置**：修改新建索引的输出目录；修改不影响已建立或已导入的索引。
- **检索后卸载索引**：开启后每次检索结束释放本次使用的索引分段以节省内存；下一次检索同一索引需要重新加载，首次响应更慢。
- **检查更新**：优先使用 gh-proxy 镜像检查 GitHub Release，官方源兜底。
- **打开后端数据目录**：在资源管理器中打开设置、收藏、历史等数据所在目录。

## 数据与目录

| 内容 | 默认位置 |
| --- | --- |
| 应用程序、Python、FFmpeg | 软件安装目录 |
| 新建索引 | `<软件安装目录>\index` |
| 设置、收藏、历史、索引注册信息 | 当前用户应用数据目录 |

## 常见问题

### 首次启动一直在准备依赖

请确认网络可访问 Python、PyPI 和 GitHub 镜像。也可以先进入界面，后端会继续在后台启动。

### 管理索引页面统计加载较慢

程序会优先展示缓存的索引列表，再在后台读取文件数、哈希数与磁盘占用。大型 SQLite 索引首次统计可能需要一定时间。

### 连续检索同一索引仍然需要重新加载

检查是否启用了「检索后卸载索引」。关闭该设置后，最近使用的索引分段会保留在内存缓存中。

### 递归扫描为何没有目录范围提示

启用递归扫描后程序会进入子目录，因此不会显示“只扫描第一层”的确认提示。关闭递归扫描时会显示该提示。

### 增量构建后索引无法识别

请确认没有在原有分段索引（含 `seg_*` 目录）的根目录直接生成根分片；程序会尽量保持原有目录结构，旧版或手动移动过的索引建议重新构建。
